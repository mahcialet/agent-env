# Flutter Androidライフサイクルの設計

[English（翻訳元）](flutter-android-runtime.md)

マニフェストは[製品契約](../product-specs/flutter-android-runtime.ja.md)で定義します。
configは厳密なデコード、appは選択、固定ソースのビルド、証拠、順序、補償を担います。
FlutterアダプターはCLI探索とビルド実行を担います。`app.FlutterProvider.Validate` は
appがビルド意図を記録する前にプロジェクトの範囲とメタデータを検査し、アダプターも
ビルド境界で再検査します。repository doctorはDockerなしで全現在checkoutを検査し、
createは固定プロジェクトを別途検査します。Androidのアプリ操作は既存の
Androidアダプターの所有確認と互換性のあるローカルADBサーバー方針を利用し、
独立したADBサーバー起動やEmulator確保を担いません。
domainとSQLiteはアプリ・ビルド・reverseの識別情報をFlutterプロセスとは独立して保持します。
アプリ記録は既存のシリアライズ済みリースデータに追加し、既存のSQLite保存処理で
リース状態と一括して保存します。新しいSQLテーブルやマイグレーションは追加しません。

## 実行順序と所有

sagaは固定コミットのワークツリーを作成し、可能な限り高コストなランタイム確保前に
選択アプリを検証・ビルドします。その後、選択ComposeとAndroidリソースを作成し、
検証したAPKをインストールし、実際のホストエンドポイントを解決してreverseを設定・確認し、
アクティビティを起動します。インストール前に既存の宣言パッケージを拒否し、処理後に新しい
パッケージを確認します。ADB reverseの接続先はローカルサーバーホストなので、エンドポイントは
ループバックTCPに限定し、リモートDockerホストを黙って置き換えません。
後続操作に進む前に、各操作の意図する識別情報を保存します。
マッピングにはアプリ、ランタイム、シリアル、エンドポイント、デバイスTCPポート、
解決したホストポートを記録します。別Emulatorのループバック空間なら同じデバイスポートを使えます。
アプリ識別には `launch_confirmed` を含め、アクティビティ起動が成功した後だけ永続化します。
起動意図だけでクラッシュ後にREADYとは判断しません。観測ではビルド終了と起動の確認に加え、
実行ファイルとプロジェクト作業ディレクトリが記録したビルド識別と一致することを要求します。

プロセス開始前のビルド意図保存で `build_unconfirmed` を設定します。クラッシュやプロセス・
出力終了の未確認時は再起動後も維持し、forceでもソースcleanupを阻止します。
永続化エラーではcleanupを停止します。初回の隔離だけでは生存中ビルドを保護できません。
同じビルド前の意図保存で `build_evidence_incomplete` も設定します。この第二のガードは、
必須の両ログ成果物と最終リース状態の保存後だけ解除します。プロセス終了確認だけでは
必要な証拠の保存を証明できません。成果物保存に失敗すると、ストア復旧後もガードを維持し、
reconcileは隔離します。通常・強制cleanupでも、証拠の調査・復旧までソースとAPKを保持します。

失敗時は所有を証明したマッピングを除去してから既存ランタイムの補償を行います。
要求したが設定を確認できなかったreverseが存在するときは除去せず保持・隔離します。
存在しなければ安全にcleanupを続行できます。
専用Emulator状態の破棄を確認できればインストール済みパッケージも消えるため、
グローバルなアンインストール工程は不要です。識別が曖昧なら予約、ソース状態、証拠を
隔離して保持します。Flutterが追跡ファイルを変更しても既存のdirtyソース保護を維持します。

観測ではAndroid所有、パッケージ存在、記録したマッピング、ビルド識別の整合性を確認し、
前面アクティビティは要求しません。名前付きテストのシリアル補間は環境による暗黙選択でなく
観測したリース識別を使います。テスト証拠では再ビルド・再インストールするコマンドと
create時APKへのブラックボックステストを区別し、stdoutと保存する実行notesの両方に残します。
APKハッシュは出自を識別し、再現性を保証しません。

## 移植可能な実行と保持する証拠

execxの引数配列、キャンセル、OS固有ラッパー処理を使います。ビルドargvの先頭要素は
Flutterバージョン探索にも使います。マニフェスト時にパスを字句検査し、実行時に固定した
プロジェクトの実パスに照合します。範囲外・シンボリックリンクのAPKや通常ファイルでない
出力は拒否します。実行ファイル、プロジェクト、APKが欠けた場合は前提条件またはビルドの
失敗であり、自動ツールチェーン取得の理由にはしません。ビルドは既存の移植可能な
実行環境を継承し、独自のアプリ環境変数マップは追加しません。
保持するargvと出力には秘匿処理を適用し、キャッシュや継承環境変数の値をメタデータに
コピーしません。ビルドのタイムアウト既定値は20分です。

Windows・macOS・Linuxのネイティブな偽アダプターテストでプロセスとパスの挙動を確認します。
実際のFlutter・Compose・高速化Emulatorの証拠は別に扱います。
明示選択した実結合テストは前提条件不足なら失敗します。UI操作とAPKの昇格・保持は対象外です。
